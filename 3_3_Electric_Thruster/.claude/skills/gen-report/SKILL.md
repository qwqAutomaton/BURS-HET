# gen-report — 知识库书面报告生成

当用户请求"生成报告"、"给出书面报告"、"整理一份报告"等时触发。

## 完整工作流

### 第一阶段：调研

1. **确定主题范围** — 理解用户提问，提取关键词和涉及的题目范围
2. **检索 wiki** — 遍历 `wiki/entries/` 和 `wiki/INDEX.md`，找到与主题相关的所有条目
3. **充分阅读 wiki** — 完整读取每一个相关条目的 md 文件，理解内容
4. **追溯原始文献** — 从每条 wiki 条目头部标注的 `REF-XXXX` 编号，查 `wiki/REFERENCES.md` 获取原始文件名，并读取 `raw/` 中的对应文件
5. **交叉验证** — 确认 wiki 条目内容与原始文献一致，补充 wiki 中未覆盖的细节

### 第二阶段：构建报告

在 `workspace/` 下创建以报告主题命名的文件夹（如 `workspace/量子计算综述/`），结构如下：

```
workspace/<报告主题>/
├── report.md              ← 报告正文
├── assets/                ← 图片、代码等附件（按需）
└── notes.md               ← 构建过程中的笔记（可选）
```

**report.md 撰写规范：**

```markdown
# 报告标题

> **生成日期**: YYYY-MM-DD
> **涉及条目**: [[条目1]](../wiki/entries/条目1.md), [[条目2]](../wiki/entries/条目2.md)
> **参考文献**: [REF-0001], [REF-0002], ...

## 摘要
...（200 字以内的概述）

## 1. 章节标题
...正文内容...

关键论断或引用处，必须标注原始文献来源 [REF-XXXX]。

## 2. 章节标题
...

## 参考文献
| 编号 | 原始文件 | 说明 |
|------|----------|------|
| REF-0001 | raw/xxx.md | 本文核心定义来源 |
| REF-0002 | raw/yyy.md | 补充背景知识 |
```

**撰写要求：**
- 严谨的书面报告风格，逻辑清晰，层次分明
- 每个关键论断必须标注 `[REF-XXXX]` 指向原始文献
- 涉及多个原始文件的交叉内容，需分别标注来源
- 报告末尾必须包含"参考文献"章节，列出所有引用的 raw 文件
- 报告中的内部引用使用相对路径超链接，指向相关 wiki 条目或 raw 文件

### 第三阶段：编译 PDF

1. 确认 `workspace/<报告主题>/report.md` 内容完整
2. 确保 `output/` 目录存在，不存在则创建
3. 使用 `mdpdf` 命令编译：

```bash
mdpdf workspace/<报告主题>/report.md output/<报告主题>.pdf
```

4. 验证 PDF 生成成功，报告文件大小

### 第四阶段：输出摘要

向用户报告：
- 生成的报告路径（md 和 pdf）
- 引用了哪些原始文献（REF 编号列表）
- 涉及了哪些 wiki 条目

## 注意事项

- raw/ 中的文件只读，不修改
- wiki/ 中的条目只读，不修改
- 所有新文件都在 workspace/ 和 output/ 中生成
- 如果 wiki 尚未构建（entries/ 为空或不存在），提示用户先运行 `/build-wiki`
- 报告文件名使用中文或英文，避免特殊字符
- 编译 PDF 前确认 mdpdf 命令可用（`which mdpdf`）
